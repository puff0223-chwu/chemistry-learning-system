# 決策紀錄

> 最新的放最上面。格式：決策、理由、被放棄的做法。由 `/wrapup` 維護。

## 後台登入：用 Supabase Auth，不用「前端密碼比對＋secret key」
- **理由**：這是純前端靜態網站，`VITE_` 開頭的變數會被打包進瀏覽器可見的 JS；把 secret key 放進去等於整個資料庫對所有訪客開放。改用 Auth 後，RLS 才能真正分辨「老師」與「學生」。
- **放棄的做法**：原規格書的前端密碼比對＋secret key。
- secret key 只在建立帳號、種子資料等一次性操作使用，不進版控。

## 登入頁預填信箱寫死在程式碼，不讀 Vercel 環境變數
- **理由**：Vercel 的 `VITE_*` 會在建置時注入並蓋過程式預設值，曾造成信箱填錯而無法登入；且信箱必須與 Supabase Auth 帳號一致（重設信也寄到這裡）。
- **放棄的做法**：`VITE_ADMIN_EMAIL` 環境變數（已棄用，可從 Vercel 刪除）。要改信箱必須改程式碼。

## 難度：資料庫存純文字，⭐ 只在畫面加
- **理由**：Excel 匯出與查詢時避免符號造成混亂或亂碼。
- 資料庫存 `基礎／進階／挑戰`；畫面顯示 ⭐／⭐⭐／⭐⭐⭐。

## 題目字級用相對倍率（0.8em／1.35em），不用固定 px
- **理由**：PK 模式有自動縮字邏輯，固定 px 會與它衝突。

## 標籤篩選採「符合任一個」
- **理由**：老師要的是「想看哪幾類就都列出來」，而非必須同時具備。
- **放棄的做法**：「必須全部符合」。

## 學習紀錄採 fire-and-forget 寫入
- **理由**：學生操作不能因網路或資料庫暫時失敗而卡住；失敗只 `console.error`。
- 為維持事件順序，前端產生 UUID 與嚴格遞增的時間戳（同毫秒 +1ms）。

## 紀錄刪除：刪 `student_sessions`，由 cascade 帶走 logs
- **理由**：一個動作即可清掉整場資料；`topic_id`、`question_id` 用 `on delete set null`，主題或題目被刪時紀錄仍保留。

## Phase 3 小遊戲由 Claude Code 逐一製作，不做成後台可編輯
- **理由**：每個化學痛點的互動邏輯差異大（配藥、濃度、pH…），難以用通用編輯器表達；以獨立頁面加 React Router 掛入選單最有彈性。
- 預定主題：①實驗室安全 ②固體／液體配藥 ③濃度計算 ④pH 計算。
