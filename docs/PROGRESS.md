### 老師實測後的第三輪修正（老師實測通過，已合併 main）
老師回報六件事，全部處理：
1. **「新增出口」那一列太靠右、選單被螢幕邊緣擋住** → 方向與場景兩個選單改成上下排，都在面板範圍內。
2. **左邊素材區被擠成一小塊，滾輪捲不動，素材多了看不到也選不到** → 
   - 原因：縮圖格子在有高度上限時被壓扁（每列只剩約 11px）。已修（`auto-rows-max`，素材庫與選圖視窗也一併修正）。
   - 左邊面板整欄可捲動（短螢幕也不會有東西被擠到看不到）；素材改成「縮小預覽（可捲動、可拖到畫布）＋『🖼️ 放大／搜尋／上傳』」，按下去是**大的素材庫彈出視窗**（可用名稱搜尋、依種類篩選、上傳、滾輪捲動，點一下放進場景）。
   - **左右面板都能收合**：面板邊緣有小圓鈕（‹ ›），收起來畫布變大，狀態會記住（螢幕窄時特別有用）。
3. **試玩時出口箭頭很靠中間、畫面不夠大** → 真正的原因是**場景縮放的量測有時漏掉**（量測元素比程式晚出現），場景停在預設的小尺寸，旁邊露出一大片延伸區；已修成元素一出現就量測，場景現在會撐滿畫面。同時出口箭頭改成**貼著螢幕邊緣**（不再貼著場景邊緣）；試玩的工具面板打開時，右邊的箭頭會自動往左讓開。
4. **試玩時四角出現黑塊** → 畫面延伸原本只補上下左右四塊鏡射，四個斜角沒補；現在四個角也用雙向鏡射補滿。
5. **條件選單分類不清楚，點擊過的隱形區域選不到** → 條件改成**老師的思考分類**，遊戲會自己記錄，不用老師另外設「記號」：
   - 📍 地點：去過／還沒去過某個地點（可選任何關卡的場景）
   - 👆 物件：點過／還沒點過某個物件（隱形點擊區、文字、圖示都選得到）
   - 🔐 題目：已經解開／還沒解開某一題
   - 🎯 任務目標：已完成某個任務目標
   - 📌 自訂進度記號（進階）：某個記號已經發生／還沒發生／幾個任選其一
   - ⏱️ 時間：遊戲開始超過幾秒
   - 白話說明會寫出名字，例如「學生去過「化學實驗室」，而且點過「鑰匙」，而且解開了「密碼鎖」」。
   - 技術：條件新增六個欄位（`visitedScenes`、`notVisitedScenes`、`clickedObjects`、`notClickedObjects`、`solvedLocks`、`notSolvedLocks`）；引擎狀態新增 `visited`／`clicked`（跟著進度存檔；舊存檔沒有這兩項也能讀）；重玩該關且「重置」開啟時會一併清掉；發布檢查會擋下「條件用到已刪除的地點／物件／題目」。

- 新條件：`hasItems`／`notHasItems`（證物袋有／沒有某物品）、`deviceStates: [{ target, state }]`（某裝置處於某狀態）。
- 引擎狀態：`devices { 裝置id: 狀態id }`、`socketsDone { 插座id: true }`；紀錄：`item_collect`、`socket_match`、`socket_wrong`、`device_state`、`item_combine`。

### 找到並修好的問題
- 答題鎖資料損壞（答案是空的、選項不是清單、題型不存在…）會讓**發布**或**學生作答**當機 → 載入時自動修復（`repairLock`），發布時也再修一次；公開版（已加密）的鎖不動。
- 資料裡有 `null`、數字等不是物件的項目（損壞的備份檔）會讓載入當機 → 載入時丟掉這些項目。
- 同一個關卡／場景／物件／群組／目標有重複的 id 會讓選單重複、事件對錯對象 → 載入時給後來的重複項新的 id。
- 事件清單裡有壞掉的步驟（`null`）會讓**健檢與遊戲**當機 → 略過壞掉的步驟。
- 對「不是答案鎖」的物件要提示、或進度指向已被刪除的題目，會當機 → 遇到時直接回傳「不可用」。
- 紀錄學生作答內容的函式遇到怪格式會當機 → 加固（記錄用，不能影響答題）。
- 「等一下」步驟的秒數欄位遇到壞資料會出現警告 → 修正。
- 發布檢查清單問題極多（上千項）時整個畫出來會卡 → 只顯示前 60 項，其餘用一行說明。
- 後台任務紀錄表格被超長姓名／班級撐破版面 → 過長就截斷，滑鼠移上去看全文。
- **整頁白畫面**（你遇過兩次）→ 新增友善錯誤頁：任何畫面出錯顯示中文說明與「重新載入」；編輯器右側面板出錯只影響那個面板（選別的物件就恢復）；網站少了資料庫連線設定（例如 Vercel 沒設環境變數）時，顯示「怎麼補」的步驟而不是空白。
- 順手讓 `src/lib/supabase.js` 在純 node 也能被載入（讓測試能涵蓋 `missionSchema` 等）。

## 2026-10-01 第 4 階段「播放器核心＋事件系統」（老師實測通過，已合併 main）

### 老師實測後的「使用直覺／介面」改版（第 4 階段內追加）
老師實測回饋：圖示太少；「點擊時」「顯示條件」「過關條件」不直覺，介面沒有暗示怎麼用。我們的診斷與改法（資料格式完全不變，舊任務照常可用）：
- **「旗標」是工程師用語，而且要自己打字（容易打成兩種寫法）** → 改稱「**進度記號**」（「學生做過的事」的便利貼），**只能從清單選或「＋新增」**，不能亂打。上方新增「📌 進度記號」總覽：每個記號在哪裡被「記住」、哪裡被「檢查」、可**改名（全任務同步更新）**，也會標出「沒人記住它」的錯誤。
- **條件是三個長得一樣的框、空白還寫「永遠成立」** → 改成「句子式條件」：每一項一行（✅ 學生已經做過…／🚫 學生還沒做過…／🔀 其中一件已經發生／⏱️ 遊戲開始超過 N 秒），下方自動顯示**白話解釋**（例如「學生已經「拿到鑰匙」，而且還沒「打開門」」），沒選完的欄位標紅。
- **「顯示條件」與「一開始是否顯示」是兩個互相打架的設定** → 合併成一題「👀 學生什麼時候看得到它？」三選一：一直看得到／一開始看不到（靠事件讓它出現）／等某件事發生才看得到（再設條件）。
- **動作只有下拉選單、空白時不知道能做什麼** → 每個步驟是一張**依種類上色的卡片**（說話＝藍、移動＝綠、物件＝橘、記憶＝紫、流程＝青、過關＝金），用句子表達並附說明；新增步驟用「＋ 接著做…」展開**帶圖示與一行說明的按鈕**；清單是空的時候先出現**「常用範例」**（說一句話、📥 撿起它、讓別的東西出現、去別的場景、需要某件事才行、點到就過關；場景則有「只有第一次進來才說」），按一下就帶入預設內容再修改。物件可選「⭐ 這個物件自己」當目標。
